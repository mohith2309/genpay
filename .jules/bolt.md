## 2025-06-17 - Redundant List Sorting in Derived Providers
**Learning:** In Dart and Riverpod architectures, methods like `Iterable.where` and sequential list grouping (e.g., populating a map from a base list) preserve the original list's element order. In `transaction_provider.dart` and `subscription_provider.dart`, the base `transactionsProvider` was already sorted descending by date. Derived providers were unnecessarily calling `.sort()` again on the filtered or grouped results, causing redundant O(N log N) processing on state updates.
**Action:** When creating derived Riverpod providers, always check if the base provider's list is already sorted. If it is, rely on Dart's order-preserving methods instead of applying redundant `.sort()` operations to optimize performance.
