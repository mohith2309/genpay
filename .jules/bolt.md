## 2026-06-29 - O(N log N) Sort vs O(N) Reduce for Max Extraction
**Learning:** Found an anti-pattern where lists were being sorted entirely (O(N log N)) just to extract the maximum element using `.first` or `.firstOrNull`. Also learned that replacing it with `.reduce()` requires careful attention to tie-breaking behavior (using `>=` instead of `>` to perfectly preserve the original `.sort().first` tie-breaking behavior). Finally, `.reduce()` on an empty collection throws a `StateError`, so an `.isNotEmpty` check is crucial.
**Action:** Always prefer an O(N) `.reduce()` or iteration to find a single max/min element instead of sorting the whole list. Ensure fallback checks are in place for empty collections and match exact tie-breaking logic using appropriate comparison operators.
