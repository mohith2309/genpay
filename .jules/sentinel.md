## 2026-07-04 - Fix DoS via Missing Payload Limits & Information Disclosure
**Vulnerability:** The Node.js proxy lacked payload limits on POST endpoints (leading to potential Memory Exhaustion / DoS) and leaked raw error messages in 500 responses (Information Disclosure).
**Learning:** Implementing payload limits using Node.js built-ins requires more than just rejecting the promise. You must explicitly handle the stream by calling `req.pause()`, sending a 413 error with `Connection: close`, and invoking `req.destroy()`. Additionally, an `if (req.destroyed) return;` check is required in the `end` event handler, and an `if (res.headersSent) return;` check is needed in the custom `send` helper to prevent errors after closing.
**Prevention:** Always implement explicit maximum byte limits using `Buffer.byteLength()` when manually buffering HTTP request streams, ensure streams are destroyed forcefully upon limits being reached, and never return raw `e.message` contents in generic catch-all HTTP 500 error handlers.
