## 2024-06-08 - Fix DoS and Data Leak in Node Backend
**Vulnerability:** The Node backend had no request payload limits on the `readBody` stream aggregator, leading to a possible DoS via excessive memory allocation. Furthermore, the global `catch` block returned the raw `e.message` to clients instead of sanitizing it, potentially leaking internals.
**Learning:** Raw HTTP streaming without tracking payload sizes inherently exposes the server to resource exhaustion. Always implement size limits when aggregating streams. Additionally, catching errors globally on router boundaries without scrubbing them allows sensitive downstream API error messages (from NVIDIA NIM or Razorpay) to be exposed directly to the UI.
**Prevention:** Track bytes accumulated during `req.on('data')` and destroy the connection `req.destroy()` if size exceeds bounds (e.g. 1MB). Always scrub errors passed to the client (e.g. return 'Internal server error') and limit explicit detailed errors to backend logs.
