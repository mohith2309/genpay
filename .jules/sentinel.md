## 2026-07-11 - Custom Node.js Server DoS and Info Disclosure
**Vulnerability:** The custom Node.js server lacked a payload size limit in `readBody`, allowing potential Denial of Service (DoS) attacks via memory exhaustion. Additionally, the global error handler exposed raw error messages (`e.message`) to clients, potentially leaking internal server details (Information Disclosure).
**Learning:** When building zero-dependency HTTP servers using Node.js built-ins, standard protections like payload size limits must be implemented manually in stream handlers (`req.on('data')`). Similarly, global `catch` blocks must sanitize error responses to prevent leaking stack traces or internal errors. Properly handling request destruction (`req.destroy()`) and preventing 'headers already sent' errors is crucial when implementing custom payload limits.
**Prevention:** Always implement a `MAX_SIZE` check when buffering request data streams, using `req.pause()`, sending a 413 response, and `req.destroy()`. Explicitly reject the promise to prevent hanging requests. For global error handlers, log the raw error internally but return a generic message (e.g., "Internal server error") to the client. Ensure `res.headersSent` is checked before attempting to send responses after stream destruction.
